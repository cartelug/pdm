# Code map and local setup

The repository deliberately has two authoring lanes. Keep them separate until an explicit, tested migration is requested.

## Lane one: institutional Astro pages

Author in `src/`, build to `build-v3/`, then `scripts/export-v3.mjs` copies approved generated HTML and `_astro/` assets into the repository root. Generated output is committed so the production server needs no Node build.

| Edit | Source |
| --- | --- |
| Homepage | `src/pages/index.astro` and `src/components/home/` |
| About, projects, model, impact and other institutional pages | `src/pages/` |
| Shared HTML head and imports | `src/layouts/InstitutionalLayout.astro` |
| Header/footer and UI components | `src/components/global/` |
| URLs, contact and social configuration | `src/config/site.ts`, `src/config/navigation.ts` |
| Shared tokens and font definitions | `src/design/tokens.json`, generated by `scripts/tokens.mjs` |
| Institutional CSS | `src/styles/tokens.css`, `base.css`, `components.css`, `shell.css`, `home.css`, `pages.css`, `motion.css` |
| Responsive campaign images | `src/components/global/ScenePicture.astro` |
| Build-time campaign lifecycle | `src/lib/campaign.ts` |
| Project data and state | `src/lib/projects.ts` and its referenced content |

Do not hand-edit root `index.html` or other generated institutional HTML; the next build overwrites it. Use the source and commit both lanes' resulting output coherently.

The backend is PHP 8.3 with PDO SQLite/SQLite3. The real ledger and operational configuration stay in private host storage outside the public source tree. Operations adds tables to the existing ledger; it is not a second set of invented public balances.

## Local development from a real clone

Use Node 22, npm, PHP 8.3 with `pdo_sqlite`/`sqlite3`, Python 3, and Chromium for browser tests. These versions match the project workflows; inspect the lockfile and workflow if the project has advanced.

```sh
git clone https://github.com/cartelug/pdm.git
cd pdm
git switch -c claude/pci-continuation
npm ci
npm run validate
```

Check `git rev-parse HEAD` and compare it with the snapshot before applying any files. A new remote commit must be reviewed, not overwritten with this package. The snapshot directory itself has no `.git` history.

To serve the committed pages and PHP locally:

```sh
php -S 127.0.0.1:8080 -t .
```

Open `http://127.0.0.1:8080/`. This development server does not provide production credentials or a copy of the live ledger. Use the isolated test fixtures for write-path testing; do not point a developer server at production storage. Astro's authoring preview covers its generated lane, while the PHP root server is useful for the whole combined tree.

## Source and output commands

```sh
npm run tokens
npm run build
npm run validate
```

Only run token generation when token source changed. Build updates generated pages, asset hashes and compiled output. `validate` includes a build too; run build/validate sequentially because they mutate the same generated files. Inspect the diff after the final run.

`scripts/export-v3.mjs` makes generated `_astro` links portable between `/` on cPanel and `/pdm/` on GitHub Pages, while canonical URLs remain production URLs. Preserve relative asset/href helpers and this export step; a root-absolute asset path can work on production and still break the static mirror.

## Protected change process

`tests/protected-campaign/baseline.json` contains 130 file hashes with reviewed exceptions. The current release has 83 presentation review entries and 14 functional review entries. Hooks and eleven frozen fragments are checked separately. For a legitimate protected presentation change, retain the old hash, date, reason and narrow authorisation/review entry, then update only the necessary recorded hash. Do not routinely record every current page as a new baseline.

Functional changes need their own explicit scope and meaningful tests. A CSS redesign is not authority to modify reconciliation, authentication or transaction logic.

## What documentation to trust

Read `ARCHITECTURE.md` with its explicit operations override, `docs/OPERATIONS-HANDOVER.md`, `docs/QUICK-START-SETUP.md` and `docs/quality/OFFICIAL-KIT-2026-10-25.md` together. `EDITORIAL-REDESIGN.md` is historical for its old font choices; `docs/archive/` is superseded. Installed packages and old image families are not proof that their older design is current.
